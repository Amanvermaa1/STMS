# Database design (PostgreSQL)

Schema is defined in `server/src/db/schema.ts` with Drizzle ORM and applied via generated SQL migrations in `server/drizzle/`. UUIDs are generated by the application (`crypto.randomUUID()`), so the schema does not depend on `pgcrypto`.

## Tables

### `users`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | Application-generated |
| `name` | varchar(80) | Required |
| `email` | varchar(254) | Unique index, normalized to lowercase |
| `password_hash` | text | bcrypt hash (cost 12) |
| `role` | enum `user_role` | `user` or `admin`, default `user` |
| `created_at`, `updated_at` | timestamptz | Default `now()` |

### `refresh_tokens`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `user_id` | uuid FK → users | `ON DELETE CASCADE` |
| `token_hash` | varchar(64) unique | SHA-256 hash of the opaque refresh token |
| `expires_at` | timestamptz | 7 days by default |
| `revoked_at` | timestamptz NULL | Set on refresh rotation or logout |
| `created_at` | timestamptz | |

Only hashes are stored. Rotation revokes the previous token, limiting replay.

### `tickets`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `author_id` | uuid FK → users | `ON DELETE CASCADE` |
| `title` | varchar(200) | 3–200 characters |
| `description` | text | 10–5000 characters |
| `category` | enum `ticket_category` | general, billing, technical, account, feature_request |
| `priority` | enum `ticket_priority` | low → urgent |
| `status` | enum `ticket_status` | open, in_progress, resolved, closed |
| `created_at`, `updated_at` | timestamptz | |

Indexes: `(author_id)`, `(status, priority)`, `(created_at)`.

### `comments`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `ticket_id` | uuid FK → tickets | `ON DELETE CASCADE` |
| `author_id` | uuid FK → users | `ON DELETE CASCADE` |
| `body` | text | 1–2000 characters |
| `created_at`, `updated_at` | timestamptz | |

Index: `(ticket_id)`.

### `activity_logs` (event actions)
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `ticket_id` | uuid FK → tickets | `ON DELETE CASCADE` |
| `actor_id` | uuid FK → users | `ON DELETE SET NULL` |
| `actor_role` | varchar(20) | Snapshot of role at event time |
| `event_type` | varchar(60) | e.g. `ticket.status_changed` |
| `metadata` | jsonb | `{ title, at, from, to, changedFields, … }` |
| `created_at` | timestamptz | |

Index: `(ticket_id)`. This is an append-only audit trail.

### `notifications`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `recipient_id` | uuid FK → users | `ON DELETE CASCADE` |
| `ticket_id` | uuid FK → tickets | `ON DELETE CASCADE` |
| `type` | varchar(60) | Domain event type |
| `message` | text | Human-readable summary |
| `read_at` | timestamptz NULL | Null means unread |
| `created_at` | timestamptz | |

Index: `(recipient_id, read_at)`.

### `user_preferences`
| Column | Type | Notes |
| --- | --- | --- |
| `user_id` | uuid PK, FK → users | `ON DELETE CASCADE` |
| `values` | jsonb | `{ dashboard, tickets, privacy }` merged on PATCH |
| `updated_at` | timestamptz | |

### `analytics_events`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `user_id` | uuid FK → users | `ON DELETE CASCADE`; nullable for future anonymous events |
| `type` | varchar(80) | Allow-listed event name |
| `metadata` | jsonb | Small scalar values only; no free text/PII |
| `created_at` | timestamptz | |

Indexes: `(user_id)`, `(type, created_at)`.

### `passkey_credentials`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `user_id` | uuid FK → users | `ON DELETE CASCADE` |
| `credential_id` | varchar(255) unique | WebAuthn credential ID |
| `public_key` | text | Base64url-encoded COSE public key |
| `counter`, `device_type`, `backed_up`, `transports` | integer / varchar / boolean / jsonb | Signature counter and authenticator metadata |
| `created_at` | timestamptz | |

Index: `(user_id)` plus a unique index on `credential_id`. Public keys are never returned by the API.

### `webauthn_challenges`
| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | |
| `type` | varchar(20) | `register` or `authenticate` |
| `challenge` | varchar(255) unique | Base64url random challenge |
| `user_id` | uuid FK → users | Nullable during email-less authentication |
| `user_identifier` | varchar(254) | Email used to scope authentication challenges |
| `expires_at` | timestamptz | Five-minute expiry |
| `created_at` | timestamptz | |

Indexes: unique `(challenge)`, `(user_id)`. Consumed and expired challenges are safe to prune.

## Relationships

```
users 1 ──── * tickets 1 ──── * comments
  │              │
  │              ├──── * activity_logs
  │              └──── * notifications
  ├──── * refresh_tokens
  ├──── 1 user_preferences
  ├──── * analytics_events
  └──── * passkey_credentials
```

## Query choices

- Enum types enforce valid category/priority/status values at the database level, in addition to Zod validation at the API boundary.
- Ownership checks are applied in the service layer on every ticket read/write.
- Filters combine `eq` predicates with escaped `ILIKE` search; sorting uses a `CASE` expression for priority so ordering is low → urgent rather than alphabetical.
- Counts and paginated rows use the same `WHERE` clause, executed concurrently.
- Search uses `ILIKE` for clarity at this scale; a `tsvector` generated column + GIN index is the documented upgrade path for larger datasets.
- Preference JSON is merged in the service layer after schema validation, keeping the stored shape predictable.
- Analytics rows are aggregate-friendly and contain only allow-listed scalar metadata.
- WebAuthn challenges are short-lived and deleted on verification; credentials store only public keys and signature counters.

## Migrations & tests

```bash
cd server
npm run db:generate   # after editing schema.ts
npm run db:migrate    # apply to DATABASE_URL
npm run db:seed       # create/update the configured admin
npm test              # applies the same migrations to in-memory PGlite
```

Tests run against PGlite (Postgres compiled to WebAssembly) using the exact same generated migrations, so constraints and SQL behavior match production without installing a database server.
